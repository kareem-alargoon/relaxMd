# RelaxMD

Calm right-to-left Markdown reader and editor for Android, built with Flutter.
See [REQUIREMENTS.md](REQUIREMENTS.md) for the full feature list and design.

## What works (phase 3: core)
- Open `.md` files (copied into the app so they can be edited and saved).
- Rendered Markdown with **per-block direction**: headings, paragraphs, list items, quotes and table cells each get RTL or LTR on their own. Code is always LTR.
- **RTL sensitivity slider** (Reading settings → `Aa`): 50% = majority rule, lower values make lines RTL even when English words outnumber Arabic ones. Plus Auto / RTL / LTR modes.
- **Zoom**: pinch with two fingers, the `− 100% +` chip, or the "Zoom for this file" slider in Reading settings (shown when a file is open). Saved per file and multiplied with the global font size.
- **Search** with a match counter and next/previous. Ignores tashkeel and tatweel and treats أ/إ/آ/ا, ة/ه, ى/ي as the same letter. Match case and whole word options.
- **Editor**: raw Markdown, marker tinting, autosave, undo/redo, find and replace, word count, Markdown toolbar.
- Table of contents drawer, reading position memory, recent files and favorites.
- Themes (Paper, Sepia, Dim, Night, System), Arabic fonts (Naskh, Amiri, Cairo, Tajawal), font size, line spacing, margins.
- Arabic and English UI (follows the phone language).

Coming in phase 4: PDF export, "Open with" from other apps, sharing, app icon, bundled offline fonts, keep screen on.

## Build the APK

You need Flutter (stable) with the Android SDK, and JDK 17.

```bash
flutter create --org com.relaxmd --project-name relaxmd --platforms android .
```

This generates the Android project files. It skips files that already exist, so the custom `android/app/src/main/AndroidManifest.xml` (internet permission, app name) and `android/app/build.gradle.kts` (release signing, below) are kept. Don't pass `--overwrite`.

```bash
flutter pub get
```

```bash
flutter test
```

```bash
flutter build apk --release
```

The APK is at `build/app/outputs/flutter-apk/app-release.apk`. Copy it to your phone and open it to install (allow "Install unknown apps" for your file manager when asked).

To install straight to a phone connected by USB (with USB debugging on):

```bash
flutter install
```

### Signing: one key, so updates install over each other

Android only lets an APK replace an installed app when both are signed with the **same** key. Without a key of our own, every build gets a fresh throwaway debug key, and the phone rejects the next APK with "App not installed" / a signature mismatch. So the release build uses one keystore that lives outside the repo.

`android/app/build.gradle.kts` is committed (unlike the rest of the generated Android project) because it holds that `signingConfig`. It reads `android/key.properties`; when that file is missing it falls back to the debug key, so a plain `flutter build apk --release` still works on a fresh clone. The trade-off: this one file no longer tracks the Flutter template, so if a future Flutter needs a different app-level Gradle file, update it by hand (everything else - `settings.gradle.kts`, the Gradle wrapper, `MainActivity.kt`, resources - is still generated by `flutter create` and keeps matching the installed Flutter).

**Make the keystore once** (keep it forever - a lost key means the app can only be updated after uninstalling it):

```bash
keytool -genkeypair -v -keystore relaxmd-release.jks -storetype JKS -keyalg RSA -keysize 2048 -validity 10000 -alias relaxmd
```

`keytool` asks for a keystore password, a few name fields (any answer works) and a key password (press Enter to reuse the keystore password). Store the file somewhere safe and backed up, **outside** the repo. `*.jks`, `*.keystore` and `android/key.properties` are gitignored, and none of them ever get committed.

**For local release builds**, write `android/key.properties` (absolute path, no quotes):

```properties
storeFile=C:/Users/you/keys/relaxmd-release.jks
storePassword=<keystore password>
keyAlias=relaxmd
keyPassword=<key password>
```

**For GitHub Actions**, add four repository secrets under Settings -> Secrets and variables -> Actions -> New repository secret ([direct link](https://github.com/kareem-alargoon/relaxMd/settings/secrets/actions)):

| Secret | Value |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | the `.jks` file, base64-encoded |
| `ANDROID_KEYSTORE_PASSWORD` | the keystore password |
| `ANDROID_KEY_ALIAS` | `relaxmd` |
| `ANDROID_KEY_PASSWORD` | the key password |

Base64 of the keystore, straight onto the clipboard (PowerShell):

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("$HOME\relaxmd-release.jks")) | Set-Clipboard
```

Avoid backslashes and `#` in the passwords: the workflow writes them into a Java properties file, which treats a backslash as an escape.

The workflow decodes the keystore, writes `android/key.properties`, builds, and deletes both again. With the secrets missing it still goes green and falls back to the debug key, with a warning on the run summary. The **Show which key signed the APK** step prints the signing certificate, so you can check that two runs report the same SHA-256 digest.

`versionCode` comes from the workflow run number (`--build-number`), so each APK counts as an upgrade of the previous one.

**First switch:** a RelaxMD installed from an older debug-signed APK has the wrong signature, so it has to be uninstalled once before the first release-signed APK will install. After that, updates install straight over the top.

### Build on GitHub instead
This repo is at <https://github.com/kareem-alargoon/relaxMd>. The workflow in `.github/workflows/build-apk.yml` builds the APK on every push to `main` (or from the Actions tab -> Build APK -> Run workflow).

**Getting it onto your phone:** sign in to GitHub in the phone browser once (the repo is private), then open <https://github.com/kareem-alargoon/relaxMd/releases/latest> and tap the `RelaxMD-<run>.apk` asset. Every green build on `main` replaces that file, so the link always serves the newest APK. Android asks you to allow installs from the browser the first time, and to confirm the update afterwards. The run's **Artifacts** section has the same APK as a zip, which is more awkward to unpack on a phone.

## Notes
- Fonts are downloaded from Google Fonts the first time they're used, so the first launch needs internet. Until then the system font is shown.
- The editor uses one direction for the whole text (a Flutter text field can't mix directions per line). The reader uses per-block direction.
